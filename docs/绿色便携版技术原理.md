# 绿色便携版技术原理

## 一、Mozilla Profile 系统

Mozilla Firefox 及其派生浏览器（包括 Zen Browser）使用 **Profile 系统**管理所有用户数据。

### Profile 数据结构

```
%APPDATA%/Mozilla/Zen/Profiles/
├── default-Nn1n2n3n/           ← 默认 profile 目录
│   ├── prefs.js                ← 用户偏好设置
│   ├── places.sqlite           ← 书签和历史记录
│   ├── favicons.sqlite         ← 图标缓存
│   ├── extension-storage/      ← 扩展数据存储
│   ├── webappsstore.sqlite     ← Web 应用权限
│   ├── storage/                ← DOM 存储（localStorage/IndexedDB）
│   └── ...（其他文件）
├── profiles.ini                ← Profile 注册文件
└── zen-portable-data/          ← （便携模式下）
```

### 关键环境变量

| 变量 | 含义 |
|------|------|
| `MOZILLA_PROFILE` | Profile 目录（绝对路径） |
| `MOZILLA_FIVE_HOME` | Gecko 安装根目录 |
| `MOZ_NO_REMOTE` | 禁止远程连接（便携版强制启用） |

### Profile 解析优先级

Mozilla Profile 服务的解析顺序（从高到低）：

1. `--profile` 命令行参数（绝对路径）
2. `MOZILLA_PROFILE` 环境变量
3. `profiles.ini` 中注册的默认 profile
4. 系统默认 Profile 目录

## 二、便携模式的路径重定向策略

### 方案 A：启动器环境变量（本项目采用）

通过启动器脚本（`zen-portable.bat` / `.sh` / `.command`）设置：

```bash
MOZILLA_PROFILE="${SCRIPT_DIR}/zen-portable-data"
MOZILLA_FIVE_HOME="${SCRIPT_DIR}"
MOZ_NO_REMOTE=1
```

并显式传递 `--profile` 命令行参数：

```bash
zen --profile "${SCRIPT_DIR}/zen-portable-data"
```

**优点**：不修改源码，适用于任何 Mozilla 派生浏览器  
**缺点**：需要用户运行启动器脚本

### 方案 B：源码级注入（适用于从源码构建的场景）

在 Mozilla Profile 服务初始化代码中注入便携模式检测逻辑：

```cpp
// 在 nsToolkitProfileService::GetDefaultProfileRootDir 中注入
nsresult _zen_portable_redirect(nsIFile* aRootDir) {
    // 获取 exe 所在目录
    nsCOMPtr<nsIFile> exeDir;
    aRootDir->GetParent(getter_AddRefs(exeDir));

    // 检查 .portable 标记文件
    nsCOMPtr<nsIFile> marker;
    exeDir->AppendNative(".portable");
    bool exists;
    marker->Exists(&exists);
    if (!exists) return NS_OK;  // 标准模式

    // 重定向到 zen-portable-data/
    nsCOMPtr<nsIFile> dataDir;
    exeDir->AppendNative("zen-portable-data");
    dataDir->Create(nsIFile::DIRECTORY_TYPE, 0755);
    dataDir->QueryReferenced(aRootDir);
    return NS_OK;
}
```

**优点**：exe 直接运行时也生效  
**缺点**：需要修补 Mozilla 源码，只能用于从源码构建的场景

### 方案 C：双重保障（推荐用于源码构建）

同时使用方案 A + 方案 B：
- 启动器脚本设置 `MOZILLA_PROFILE`（第一优先级）
- 源码注入便携检测（备用保障）

## 三、`.portable` 标记文件

`.portable` 标记文件用于：

1. 让源码注入的逻辑能区分「便携模式」和「标准模式」
2. 作为打包时的存在性检查标志

**标记文件内容**：空文件（无内容）  
**路径**：exe 同级目录  
**大小**：0 bytes

## 四、CI 便携封装流程

由于 Zen Browser 基于完整 Mozilla Firefox 源码构建（约 200k+ 文件，60GB+ 磁盘需求，2-4 小时/平台），CI runner 无法实时从源码重建。本项目采用 **下载上游预构建 Release 包再封装** 的方式：

```
GitHub Actions CI
  ├── prepare job：通过 GitHub API 解析上游 tag
  │
  ├── build-macos：下载 .dmg → hdiutil 挂载 → 提取 Zen.app
  │                  → 添加 .portable + zen-portable.command + README
  │                  → 打包为 zip
  │
  ├── build-windows：下载 .exe → 7-Zip 解压 NSIS
  │                    → 添加 .portable + zen-portable.bat + README
  │                    → 打包为 zip
  │
  └── build-linux：下载 .tar.xz → tar xJf 解压
                     → 添加 .portable + zen-portable.sh + README
                     → 打包为 tar.gz
```

## 五、平台差异

### Windows

| 路径 | 值 |
|------|----|
| exe 位置 | `D:\ZenBrowser\zen.exe` |
| Profile 目录 | `D:\ZenBrowser\zen-portable-data\` |
| 标记文件 | `D:\ZenBrowser\.portable` |
| 系统残留 | 无 |

### macOS

| 路径 | 值 |
|------|----|
| app 位置 | `/Users/zen/Zen.app` |
| Profile 目录 | `/Users/zen/zen-portable-data/` |
| 标记文件 | `/Users/zen/.portable` |
| 系统残留 | 无（`~/Library/Application Support/Zen/` 不会创建） |

### Linux

| 路径 | 值 |
|------|----|
| 二进制 | `~/zen-browser/zen` |
| Profile 目录 | `~/zen-browser/zen-portable-data/` |
| 标记文件 | `~/zen-browser/.portable` |
| 系统残留 | 无（`~/.mozilla/zen/` 不会创建） |

## 六、便携模式验证方法

### 1. 检查 Profile 位置

启动浏览器后，访问 `about:support`，在「Profile 目录」字段查看：

| 模式 | 预期值 |
|------|--------|
| 便携模式 | `<exe路径>/zen-portable-data/default-*` |
| 标准模式 | `<系统目录>/Mozilla/Zen/Profiles/default-*` |

### 2. 检查系统残留

便携模式下，以下目录不应存在任何文件：

- Windows: `%APPDATA%/Mozilla/Zen/`
- macOS: `~/Library/Application Support/Zen/`
- Linux: `~/.mozilla/zen/`

### 3. 迁移测试

1. 在便携数据目录中修改书签
2. 关闭浏览器
3. 将整个便携目录拷贝到新位置
4. 在新位置运行启动器
5. 书签应正常显示

## 七、与 Gridea Pro Portable 的对比

| 维度 | Gridea Pro Portable | Zen Browser Portable |
|------|--------------------|----------------------|
| 引擎 | Wails (Go) | Mozilla Firefox (C++) |
| 数据管理 | Go 代码中设置配置目录路径 | Mozilla Profile 系统 |
| 便携机制 | 启动器环境变量 + `--profile` 参数 | 启动器环境变量 + `--profile` 参数 |
| 标记文件 | `.portable` | `.portable` |
| 数据目录名 | `Gridea Pro/` | `zen-portable-data/` |
| 构建方式 | 从源码实时构建 | 下载上游预构建 Release 包再封装 |
| 构建时间 | ~10 分钟 | 即时（下载 + 封装） |
| 构建空间 | ~10 GB | 无需（直接下载二进制） |
